# Resumo — UX

## O que esta pasta cobre
Princípios de design de interação, estratégias de engajamento e decisões visuais do Daily Quest.

## Quando consultar esta pasta
Antes de qualquer decisão de interface: como apresentar uma feature, que feedback dar ao usuário, como tornar uma interação mais satisfatória.

## Mapa de arquivos
| Arquivo | Quando usar | Sinal de busca |
|---------|-------------|----------------|
| `principios.md` | Decisões de filosofia de design e engajamento | motivação, retenção, feedback, atrito, gamificação |

## Conexões com outras pastas
| Se o contexto for... | Consulte também... | Motivo |
|----------------------|--------------------|--------|
| Implementar nova feature | `features/` | Spec define o comportamento, UX define a forma |
| Tokens visuais e animações | `tecnico/arquitetura.md` | Design system já definido no código |
| O que o produto deve ser | `produto/visao.md` | Tom do produto guia decisões de UX |

## Quando criar novo arquivo aqui
Quando uma decisão de UX for complexa o suficiente para documentação própria — exemplos: sistema de notificações, onboarding, fluxo de criação de hábito, design para mobile.
